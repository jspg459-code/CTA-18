# StreamTV V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the former CTA-18 application with a production-ready StreamTV IPTV player V1.

**Architecture:** Next.js App Router for the responsive UI and server routes, Supabase for Auth/Postgres/RLS, and Vercel for hosting. Playlist parsing and provider credential handling stay server-side; the browser handles playback of compatible user-authorized streams.

**Tech Stack:** Next.js, React, TypeScript/JavaScript, Supabase, HTML5 video, CSS.

**Spec:** `docs/superpowers/specs/2026-09-15-streamtv-design.md`

## Global Constraints

- StreamTV is free in V1.
- Users can manage multiple playlists.
- Supported sources: M3U/M3U8 and Xtream Codes.
- Only user-supplied or otherwise authorized streams are supported.
- No bundled pirate/copyright-infringing channel catalog.
- Responsive dark premium UI matching the approved StreamTV mockup.
- User data is isolated with Supabase RLS.
- Do not expose Supabase service-role credentials to the browser.
- Remove the active CTA-18 UI/API behavior.
